# Setting up `/lnr-plan` in your own repo

`/lnr-plan` ships with **placeholder** domain data (`core`, `billing`,
`notifications`, `internal-ops`) — it only shows the shape `WORLD_MAP` needs.
Before using the command for real, replace that placeholder with your own
repo's actual business domains and the modules inside each one.

## 1. Install the files

Copy `commands/lnr-plan.md`, `commands/lnr-plan.template.html`, and
`commands/lnr-plan.worldmap.json` into your repo's `.claude/commands/`
folder (create it if it doesn't exist). All three must sit directly in
that folder, since `lnr-plan.md` refers to the other two by that relative
path.

## 2. Generate your own `WORLD_MAP`

Run the following as a prompt to your own agent, in your own repo, once:

---

> Read this repo's own code to map out its real business domains and the
> modules inside each one, then fill in `.claude/commands/lnr-plan.worldmap.json`
> and the matching `WORLD_MAP` constant in
> `.claude/commands/lnr-plan.template.html` with the result, replacing the
> placeholder domains/modules currently there.
>
> A **domain** is a business-level area (e.g. "Billing", "Notifications",
> "Auth") — the kind of grouping a non-engineer stakeholder would recognize,
> not a technical layer. A **module** is a meaningful sub-area inside one
> domain (e.g. "Invoices" and "Payments" inside "Billing").
>
> Look for signals like: top-level feature folders in the backend and
> frontend, groupings in a shared/common package, distinct database
> collections or tables, and any existing domain/module registry this repo
> might already keep (a file that maps areas to folders or collections,
> if one exists — read it first if so, it's your best source of truth).
> Keep this to the real, current structure — don't invent domains for
> hypothetical future features.
>
> Always keep one domain as a catch-all for cross-cutting, not-really-
> one-domain's-own code (shared config, migrations, infra, generic
> utilities) — name it `internal-ops` or whatever fits this repo's own
> vocabulary better.
>
> For `lnr-plan.worldmap.json`: write `domains` (each `{ id, name, color }`,
> with a distinct, deliberately-picked hex color per domain — don't reuse
> colors) and `modules` (each `{ id, name, domainId }`, with `id` written as
> `<domainId>.<module-slug>`). Keep the existing `_comment` field's wording
> but drop the "PLACEHOLDER DATA" sentence once you've replaced it for
> real.
>
> Then open `lnr-plan.template.html`, find the `const WORLD_MAP = {...}`
> block (it's commented "fixed domain/module registry... must mirror
> lnr-plan.worldmap.json verbatim"), and replace its contents with the
> exact same `domains`/`modules` data you just wrote to the JSON file —
> the two must match byte-for-byte in structure (JS object literal vs.
> JSON, same data). Also drop that block's "PLACEHOLDER DATA" paragraph
> once replaced.
>
> Report back the domain/module list you landed on before finishing, in
> case any of the groupings need a human correction.

---

Expect to correct the first draft by hand — an agent's first pass at
"what are this repo's real domains" is a reasonable starting point, not
a final answer. Once you're happy with it, `/lnr-plan` treats `WORLD_MAP`
as fixed: it's edited by hand, rarely, never regenerated by a plan run.

## 3. Check your issue tracker

The command is written against Linear's tool names (`get_issue`,
`list_comments`, `get_issue_status`). If you use a different tracker,
either have your agent swap in that tracker's equivalent calls in
`lnr-plan.md` Step 0, or just skip issue linking — the command still
works from a free-text ask with no linked issue, it just never shows an
issue badge.

## 4. Optional extras `lnr-plan.md` references

These aren't required — the command degrades gracefully without them —
but if you want the exact same output it was designed for:

- **A plan-format convention.** Step 4 mentions following "your own
  plan-format convention" for `FULL_PLAN_MD`'s section order. If you
  don't keep one, the command's own default section list is used as-is.
- **[Conductor](https://conductor.build).** The template's "Send notes to
  Conductor" button and deep links only do anything if you use it.
  Otherwise it's inert — safe to ignore, or strip out of the template.
- **A browser-automation tool**, for Step 6's verification pass (anything
  that can open an HTML file and check it renders right — a headless-browser
  skill, Playwright, or just opening it by hand).
